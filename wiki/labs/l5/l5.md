## Activity 1 — Test organization

Unit tests live in `tests/unit/` and integration tests in `tests/integration/`, with one integration spec per feature. The Wiki spec uses the `wiki` tag for the feature and `smoke`, `functional`, `boundary`, `negative` and `e2e` for case selection. Use the smoke tag for a quick local check of the empty Wiki. Continuous testing (CT) runs the full Wiki regression suite, including that smoke case.

## Activity 5 — Integration and continuous testing

| Workflow | Triggers | What it runs | Artifact |
| --- | --- | --- | --- |
| [CI](../../../.github/workflows/ci.yml) | Pull requests and pushes to `main` and `develop` | Repository-wide typecheck and lint, then all framework unit tests | `ci-reports` with JUnit and V8 coverage |
| [CT](../../../.github/workflows/ct.yml) | Same-repository pull requests to `main` or `develop`, manual dispatch, and daily at midnight in Colombia | Runs the full Wiki suite once per trigger, including smoke, functional, boundary, negative and E2E cases | `wiki-ct-reports` with JUnit, HTML, Pino logs and summaries |

CT calls the [temporary Wiki script](../../../scripts/tmp/generate-individual-test-reports.ts), which passes the Wiki-only Vitest configuration to the [shared report runner](../../../scripts/generate-test-reports.ts). Once all feature suites are ready and their Actions variables and secrets are configured, point CT at `bun scripts/generate-test-reports.ts` and remove `scripts/tmp/`. The shared runner's default configuration includes all integration specs.

Each CT run writes to its own directory under `reports/ct/` and returns Vitest's exit status. The two consecutive local rounds and the later full-suite run are recorded in [Matthew’s execution results](l5_matthew.md#activity-2--execution-and-reports). The workflows upload any available reports for failed jobs.

Configure `GITLAB_WIKI_PROJECT_ID` and `GITLAB_WIKI_EMPTY_PROJECT_ID` as Actions variables. `GITLAB_BASE_URL` is optional. Store dedicated GitLab automation credentials as the Actions secrets `GITLAB_TOKEN_EDITOR` (`api`) and `GITLAB_TOKEN_READER` (`read_api`). The editor credential needs write access to the test Wiki and read access to the empty Wiki. Set `CT_SCHEDULE_DISABLED` to `true` to pause scheduled runs.

Both workflows are configured in this branch. The execution results above came from local runs. GitHub-hosted runs and artifact uploads still need verification after the workflows are published. Scheduled and manual triggers require the workflow on the default branch. [GitHub Actions events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)
